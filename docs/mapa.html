2. Cómo se conecta, v0.1

Navegador (web)→ HTTP + SSE → API (FastAPI)→ Cerebro: generar()→ claude -p→ tu suscripción
API→ guarda y lee → Datos (Postgres en Docker)

Regla de dependencias: api importa de cerebro y datos; cerebro y datos solo importan de config y nunca entre sí.

Cómo se conecta, v1.0

Navegador (web, paneles) → HTTP + SSE → API (FastAPI) → flujo: el grafo de LangGraph → cerebro: generar() → claude -p u otra suscripción
flujo → llama a → plan aprender material tono fuentes y research
flujo, plan, aprender, fuentes → guardan y leen → datos: Postgres + pgvector ← migraciones de Alembic
API → encola → trabajos → ejecutan → material y fuentes → avisan por SSE → Navegador
seguridad/entrada → API → seguridad/salida · y observar registra trazas y métricas de todo el recorrido
compose.yaml levanta → Postgres servidor web · Caddyfile expone la web y la API · ci.yaml pasa pytest, build y evals

Lo que se mantiene de la v0.1: api importa de las demás piezas, y cerebro y datos solo importan de config. Cómo se extiende esa regla a flujo, plan, aprender y el resto es una decisión pendiente (un ADR cuando toque), no algo ya fijado en CLAUDE.md.

Basado en CLAUDE.md, la estructura real de servidor/ y web/ y el «Mapa del producto» del capítulo 1. El estado de cada carpeta es el de hoy y cambia al construir.
